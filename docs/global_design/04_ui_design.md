# UI設計書

「MARGIN | TECH JOURNAL」のモック（トップ／記事一覧、記事詳細）に基づく画面設計。参考リポジトリの`04_ui_design.md`に相当する。

> 寸法・色は、もともとモックのスクリーンショットから読み取った**目安値**（モック本体: [margin-tech-notes](https://margin-tech-notes.hondatakahiro371.chatgpt.site/)）。実装で確定した箇所は、実装の値（Tailwindのクラス名など）で記載している。

## 1. 画面一覧

> 旧案の「記事一覧（`/blogs`）」は廃止し、トップページに統合した。トップページの最新記事セクションが、フィルタ・検索・ページネーションを備えた全記事一覧を兼ねる。

| 画面 | パス | 概要 | モック |
|---|---|---|---|
| トップページ（記事一覧を兼ねる） | `/` | ヘッダー（キャッチコピー行を含む）＋（絞り込み時のみ）パンくず＋最新記事（フィルタ・検索・ページネーション）＋サイドバー | 画像①（絞り込みなし）／画像③④（カテゴリ・月絞り込み時のパンくず・見出し切り替え）。ページネーション部は別途共有されたモック画面を参照 |

| プロフィール | `/profile` | パンくず＋タイトル＋メイン画像＋本文＋サイドバー | 画像⑤（パンくず）／参考画像（別ブログの例。本文構成のみ） |

| 免責事項 | `/disclaimer` | パンくず＋タイトル＋本文（新規。フッターからのみ遷移） | なし（`/about`と同じ構成で作る） |
| 404 | （自動） | 存在しないURL・記事IDの場合。見出し＋説明＋HOMEへのリンク（[8.6](#86-404ページnot-found)参照） | なし |

- 旧案では「もっと見る」ボタンで`/`から`/blogs`（全件一覧）へ遷移していたが、`/`自体がページネーション付きの全件一覧になったため、この遷移は廃止した

### 3.1 グリッド

| 項目 | 仕様（目安） |
|---|---|

### 3.2 ヘッダー

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 紺の上端ライン（全ページ共通）
 [ロゴ] KAIZEN │ 技術ブログ              記事一覧  このブログについて  プロフィール
 つくって、試して、わかったこと。Web開発の学びをここに。   ▔▔▔▔▔  ← 現在ページに青い下線
   ↑ キャッチコピー（ロゴの下）
────────────────────────────────────────────────────────────────────
```

- ロゴ: ロゴ画像（`public/logo.svg`）＋「KAIZEN」（大文字・字間広め・太字）＋縦線＋「技術ブログ」（小さく・グレー）。モックの「m. MARGIN」から、サイト名に合わせて変更した
- ナビ: 「記事一覧」「このブログについて」「プロフィール」はすべて内部リンク（`/`系は「記事一覧」、`/about`、`/profile`）。モックの「プロフィール ↗」は外部リンク表記だったが、内部ページ化に伴い↗アイコンは外す
- **アクティブ表示**: 現在のパスに対応する項目を青文字・太字＋2pxの青いアンダーライン。`/`と`/blogs/[id]`はいずれも「記事一覧」をアクティブとする（`NAV_ITEMS`の`activePrefixes: ["/blogs/"]`）。現在のパスの判定にはClient Componentの`usePathname`が必要なため、リンク部分のみ`NavLink`として切り出し、ヘッダー本体はServer Componentのままにする
- ヘッダー最上部に紺色の細いライン（4px、`border-t-4 border-t-slate-800`）が付く。モック（トップページ）でも確認できたため、記事詳細だけでなく全ページ共通とする
- **キャッチコピー**: ロゴの下に、`つくって、試して、わかったこと。Web開発の学びをここに。`を1行で表示する。ページによる出し分けはなく、**全ページ共通でヘッダーの一部として表示**する（旧案では絞り込みなし時のトップページだけに出す案だったが、モックに合わせてヘッダー自体の一部に変更した）。スマホ・タブレットでは非表示（下記）
- キャッチコピー文言は変更頻度が低いため、`shared/lib/constants.ts`に定数として持つ（`CATCH_COPY`）

**スマホ・タブレット（〜1023px）の表示: 1段＋ダイアログ**

```
┌──────────────────────────────┐
│ [ロゴ] KAIZEN │ 技術ブログ   🔍 ☰ │  ← ロゴと、検索・メニューのボタン
└──────────────────────────────┘
  🔍 → 画面下からせり上がる検索ダイアログ（検索ボックス＋閉じるボタン）
  ☰ → 画面右から出るメニューダイアログ（MENU＋ナビ3項目＋閉じるボタン）
```

| 項目 | 仕様 |
|---|---|
| 構成 | ロゴと、右端に検索ボタン（虫眼鏡）・メニューボタン（三本線）の1段。PC（1024px以上）では左にロゴ＋キャッチコピー・右にナビ |
| ナビ | PCのナビ（`<nav aria-label="メインナビゲーション">`）は非表示にし、メニューダイアログ内に縦並びで表示する（`<nav aria-label="モバイルナビゲーション">`）。項目は同じ`NAV_ITEMS`を使い、選んだらダイアログを閉じる |
| 検索 | 検索ダイアログの中にサイドバーと同じ`SearchBox`を置く。サイドバーはメインの下に回るため、画面上部から検索できるようにした |
| ダイアログ | HTML標準の`<dialog>`（`showModal()`）＋daisyUIの`modal`（検索は`modal-bottom`、メニューは`modal-end`）。閉じるボタンと背景のタップは`<form method="dialog">`で閉じる。開閉の状態をReactで持たないので、`useRef`だけで済む |
| 余白 | 左右の余白はスマホ16px（`px-4`）、タブレット32px（`sm:px-8`）、PC64px（`lg:px-16`） |
| キャッチコピー | スマホ・タブレットでは非表示（`hidden lg:block`） |
| 画面上部への固定 | **全幅で固定**（`sticky top-0 z-50`）。1段に収まって背が低くなったため、スマホでも固定して本文の読める範囲を圧迫しない |

- 当初は「スマホは2段構成（ナビを横一列）・ハンバーガーメニューは採用しない・固定はPCのみ」としていたが、1段＋検索・メニューのダイアログ方式に変更した。スマホではサイドバーがメインの下に回るため、検索をヘッダーから開けるようにもしている
- ボタン・ダイアログの部分だけを`shared/components/layout/MobileMenu.tsx`（Client Component）に切り出し、ヘッダー本体はServer Componentのままにする
- 記事詳細のシェア列はPCでのみ`sticky`（`lg:top-40`）

### 3.3 ヘッダー直下のパンくず

トップページの絞り込み時・記事詳細・固定ページ（about・プロフィール・プライバシーポリシー・免責事項）では、ヘッダーのすぐ下にパンくずの帯が入る。それ以外（トップページの絞り込みなし時）は何も入らず、本文がそのまま続く。

| 状態 | 表示内容 | 対象ページ |
|---|---|---|
| パンくず帯 | `HOME`（青・リンク→`/`）＞ 現在地（グレー、`aria-current="page"`） | トップページの絞り込み時（画像③④）、記事詳細（画像②）、プロフィール（画像⑤）、about・プライバシーポリシー・免責事項 |
| なし | ヘッダーの直後に本文（最新記事セクション）が続く | トップページの絞り込みなし時（画像①） |

- 旧案にあった大見出し「技術と、日々の余白。」は廃止した。トップページのh1は、絞り込み時のみ最新記事セクションの見出しが兼ねる（[5.1](#51-パンくずと見出しの切り替え)参照）
- パンくずの部品（`Breadcrumb`。`{ label, href? }`の配列を受け取る）は共通化し、上記のページで再利用する（[11章](#11-コンポーネント対応表)参照）

### 3.4 フッター

参考サイト（[nochitoku-it.com](https://www.nochitoku-it.com/)）のフッターを参考にした、リンク行＋コピーライトだけのシンプルな構成とする。

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 紺の帯（全幅）
            HOME    |    プライバシーポリシー    |    免責事項          ← リンク行（中央寄せ）

                          © 2026 KAIZEN.                               ← コピーライト行（中央寄せ）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

| 要素 | 仕様（目安） |
|---|---|
| 背景 | 全幅の紺（Navy、[4章](#4-カラータイポグラフィ目安)参照）。ヘッダー上端ラインと同系色で、ページの上下を締める |
| 文字色 | 白（コピーライトは白の不透明度を少し下げてもよい） |
| 高さ・余白 | 上下の余白は約24〜32px。2行（リンク行・コピーライト行）を縦に並べ、行間は約16px |
| リンク行 | `HOME`（→`/`）、`プライバシーポリシー`（→`/privacy-policy`）、`免責事項`（→`/disclaimer`）を中央寄せで横並び。項目間に縦線（`|`）の区切りを入れる。文字サイズは約14px |
| 区切り線 | 装飾なので読み上げ対象にしない（CSSの疑似要素で描く、または`aria-hidden`を付ける） |
| ホバー | 下線を付ける程度の控えめな表現。フッター内ではアクティブ表示（現在ページの強調）はしない |
| コピーライト行 | `© {開設年} KAIZEN.`。文字サイズは約12px |
| 配置 | 全ページ共通。`app/layout.tsx`でメインコンテンツの後ろに置く。本文が短いページでも画面下端に来るように、`body`（またはラッパー）を縦方向のflexにして`min-h-screen`とし、メイン側を伸ばす |

- 旧案にあった「ロゴ」「ページ先頭へ戻るリンク」はフッターから外す。ロゴはヘッダーにあり、ページ先頭へ戻る操作は右下固定の[ScrollTopボタン](#35-ページ先頭へ戻るボタンscrolltop)が担うため、重複させない
- ヘッダーのナビ（記事一覧・このブログについて・プロフィール）はフッターに繰り返さない。フッターのリンクはサイトの付帯情報（HOME・規約系ページ）に絞る
- コピーライトの年は、ブログ開設年を固定値で持つ（`© 2026 KAIZEN.`）。現在年を`new Date()`で動的に出す方式は、毎年の更新は不要になるが描画時刻に依存するため採用しない。文言は`shared/lib/constants.ts`に定数（`COPYRIGHT`など）として持つ
- フッターのリンク一覧も変更頻度が低いため、`shared/lib/constants.ts`に配列の定数（`FOOTER_LINKS`など。`{ label, href }`の配列）として持ち、コンポーネント側は`map`で描画する
- フッターは状態を持たないため Server Component とする（[11章](#11-コンポーネント対応表)参照）

### 3.5 ページ先頭へ戻るボタン（ScrollTop）

- 右下固定の円形ボタン（上向きシェブロン）。スクロール量に関係なく常に表示する
- クリックでページ最上部へスムーズスクロール。`aria-label="ページの先頭へ戻る"`

| 項目 | 仕様 |
|---|---|
| 置き場所 | `shared/components/layout/ScrollTopButton.tsx`。クリック処理（`window.scrollTo`）が必要なためClient Component。`app/layout.tsx`のフッターの後ろに置き、全ページで表示する |
| 表示条件 | 常に表示する。当初は`window.scrollY`が400pxを超えたら表示する仕様（`useSyncExternalStore`で`scroll`イベントを購読）だったが、スクロール量の監視をやめて常時表示に変更した |
| 位置・見た目 | 画面右下（`fixed bottom-6 right-6`）、直径48px（`size-12`）の円形。白地に薄いグレーの枠線（`border-slate-300`）とグレーの上向きシェブロン、影付き。ホバーで枠線・アイコンを少し濃くする。キーボードフォーカス時は青いアウトライン。ヘッダー（`z-50`）より下の`z-40` |
| 動き | `window.scrollTo({ top: 0, behavior })`。OSで「視差効果を減らす」を設定している人には`behavior: "auto"`（瞬時に移動）、それ以外は`"smooth"`。`prefers-reduced-motion`で判定する |
| 要素 | `<button type="button">`。アイコンのSVGは`aria-hidden` |

- 見た目とクリック時の動きだけの部品なので、テストは書かない（テスト方針の「見た目の検証はしない」に該当）

### 5.1 パンくずと見出しの切り替え

トップページのヘッダー直下は、絞り込み状態によって表示が変わる（[3.3](#33-ヘッダー直下のパンくず)参照）。キャッチコピーはヘッダーの一部として全ページ共通で常時表示するため、ここでの出し分け対象ではない。旧案にあった大見出し「技術と、日々の余白。」、および最新記事セクションの固定見出し「最新の記事」はいずれも廃止した（ページネーションで後方のページを見ているときに「最新」と表示するのが実態に合わないため）。

| 状態 | ヘッダー直下のパンくず | 最新記事セクションの見出し（h1） | 該当画像 |
|---|---|---|---|
| 絞り込みなし（初期表示） | なし（ヘッダーの直後に本文が続く） | なし（見出しテキストは表示しない） | 画像① |
| カテゴリ絞り込み中 | `HOME ＞ {カテゴリ名}` | `「{カテゴリ名}」の記事一覧` | 画像③ |
| 月（アーカイブ）絞り込み中 | `HOME ＞ {YYYY年M月}` | `{YYYY年M月}の記事一覧` | 画像④ |

- カテゴリ・月のいずれも指定されていない場合はパンくず・見出しともになし、いずれか一方でも指定されていれば両方を出す。両方が同時に指定された場合（URLを直接編集したときのみ起こる）は、絞り込み自体はAND条件で行い、パンくず・見出しはカテゴリを優先して表示する（`features/blog-list/lib/list-metadata.ts`の`buildFilterLabel`・`buildArticleListHeading`）
- キーワード検索（`keyword`）のみの絞り込みでは、パンくず・見出しともに出さない
- ルーティングは変更しない。カテゴリ・月の絞り込みは引き続き`/`への`searchParams`（[5.5](#55-urlパラメータ)参照）で表現し、専用URL（例: `/categories/[slug]`）は作らない
- ページのh1は、絞り込み時のみこの見出し（`「◯◯」の記事一覧` ／ `◯年◯月の記事一覧`）が兼ねる。絞り込みなし時はh1を置かない（視覚的に非表示のh1を用意する案もあるが、現状は置いていない）。キャッチコピー・パンくず自体はh1にしない

- 要約（`excerpt`）はカードに表示しない。タイトルで内容が十分伝わるため。要約はmeta description・OGPの説明文にのみ使う（[10.1](#101-ページごとのメタデータ)参照）

| ブロック | 内容 |

- カテゴリー・アーカイブの件数は、絞り込み前の全記事から集計する

### 5.5 URLパラメータ

トップページの絞り込み・ページネーション状態はURLの`searchParams`に反映し、共有・ブックマーク・ブラウザの戻る操作に対応する。

| パラメータ | 例 | 用途 |
|---|---|---|
| `category` | `?category=TypeScript` | 選択中のカテゴリ（URLエンコード。例: `Next.js`） |
| `keyword` | `?keyword=hooks` | 検索キーワード |
| `month` | `?month=2026-09` | アーカイブの絞り込み |
| `page` | `?page=2` | 現在のページ番号（既定1） |
| `pageSize` | `?pageSize=20` | 表示件数（既定10） |

- カテゴリ・検索・月・表示件数のいずれかを変更したら`page`は1にリセットする（サイドバーのリンク・検索フォームは`page`を含まないURLへ移動し、表示件数セレクトは`page=1`を付ける）
- 不正な値は既定値として扱う（`page`が正の整数でなければ1、`pageSize`が10・20・30以外なら10）。`page`が総ページ数を超える場合は最終ページを表示する
- ページネーションのリンクは、既定値の`page=1`・`pageSize=10`をURLに含めない（`buildArticlesHref`）
- サイドバーのカテゴリー／アーカイブは、この`searchParams`を使ってトップページの該当状態へ直接ジャンプする（旧`/blogs`への遷移は廃止）
- 絞り込み・ページネーションの計算は、トップページ（Server Component）が`searchParams`を受け取り、全件取得した記事に純粋関数を適用して行う（[04_data_fetching_policy.md](../../frontend/docs/04_data_fetching_policy.md)参照）。記事数が増えたら、microCMS側で絞り込む方式（`limit`/`offset`/`filters`）へ移行する

### 6.1 シェアボタン（ShareButtons）

参考: Qiitaの記事詳細ページ左側のアクション列（いいね・ストックの下にあるX / Facebook / はてなブックマーク）。本ブログはいいね・ストック機能を持たないため、シェアの3つだけを並べる。

**配置**

| 幅 | 配置 |
|---|---|
| PC（1024px以上） | 記事本文（`<article>`）の左側に専用の細い列（幅48px程度）を設け、アイコンを縦に並べる。`sticky`でヘッダー下に固定し、本文をスクロールしても画面内に残す |
| タブレット・スマホ（〜1023px） | 左列は取らず、本文の末尾にアイコンを横一列で並べる（読み終えたタイミングで共有できる位置） |

- コンポーネントは1つだけ描画し、CSS（`grid`と`order`・`flex-col`/`flex-row`の切り替え）で位置と向きを変える。PC用とスマホ用を2回描画すると、スクリーンリーダーに同じリンクが二重に読まれるため避ける
- 記事の左列はメイン領域の中に取る（サイドバー含む全体の2カラム構成は変えない）

**見た目**

| 項目 | 仕様 |
|---|---|
| アイコン | 各サービスのロゴ（Xは黒、Facebookは青`#0866FF`、はてなブックマークは青`#00A4DE`の「B!」）。表示サイズは24px程度、クリック範囲は40px四方以上を確保する |
| 背景・枠 | Qiitaと同様に枠なし・背景なし。ホバー時に薄いグレーの円背景を出す程度 |
| ツールチップ | ホバー時とキーボードフォーカス時に表示する。文言は下表のとおり。PCではアイコンの右側、スマホ（横並び）では上側に出す。黒地・白文字・角丸の吹き出し |

| サービス | ツールチップ文言 | 共有画面のURL（`url`・`text`等はURLエンコードする） |
|---|---|---|
| X | `X（Twitter）でシェアする` | `https://x.com/intent/post?text={記事タイトル}%0A{記事URL}`（`url`パラメータは使わず、タイトル・改行・記事URLを`text`にまとめる。`url`で渡すとX側がタイトルとの間に半角スペースを入れ、改行できないため。カードは本文中のURLのOGPから作られる） |
| Facebook | `Facebookでシェアする` | `https://www.facebook.com/sharer/sharer.php?u={記事URL}`（タイトルは渡せず、OGPから取得される） |
| はてなブックマーク | `はてなブックマークに追加する` | `https://b.hatena.ne.jp/add?mode=confirm&url={記事URL}&title={記事タイトル}` |

- ツールチップはdaisyUI v5の`tooltip`クラス（`data-tip`属性に文言を入れる。位置は`tooltip-right`／`tooltip-top`をブレークポイントで切り替える）で実装し、JavaScriptを使わない
- `title`属性は付けない。Qiitaのスクリーンショットではカスタムのツールチップとブラウザ標準のツールチップ（`title`属性由来の「ポスト」等）が二重に出ているため、本ブログでは片方に揃える

**挙動**

- `<a href={共有画面のURL} target="_blank" rel="noopener noreferrer">`の通常リンクで開く。ポップアップウィンドウ（`window.open`でサイズ指定）にはしない。クリック時の処理が不要なので、コンポーネントはServer Componentのままにできる
- 各SNSのSDK（埋め込みスクリプト）は読み込まない。表示速度とプライバシー（外部スクリプトによるトラッキング）のため、共有画面へのリンクだけで実現する
- 記事URLは絶対URLが必要なため、`shared/lib/site-url.ts`の`buildAbsoluteUrl(`/blogs/${id}`)`で組み立てる。内部では`getSiteUrl()`が環境変数`SITE_URL`を読み、未設定ならエラーにする（[07_api_design.md](./07_api_design.md)参照）
- シェアURLの組み立ては純粋関数（記事URLとタイトルを受け取り、3サービス分の`{ service, label, href }`を返す）に切り出し、コンポーネントはその結果を`map`で描画するだけにする。エンコード漏れを防ぐため、文字列連結ではなく`URLSearchParams`で組み立てる

**OGP（シェア時のカード表示）**

- XやFacebookで表示されるカード（タイトル・説明・画像）は、共有画面のURLではなく記事ページのOGPから作られる。シェアボタンと同じタイミングで、記事詳細の`generateMetadata`に`openGraph`（`title`・`description`・`images`にアイキャッチ）と`twitter`（`card: "summary_large_image"`）を設定する
- ルートの`metadata`に`metadataBase: new URL(SITE_URL)`を設定し、OGP画像などの相対URLが絶対URLに解決されるようにする

**MVP対象外（将来検討）**

- Qiitaの「…」メニューに相当するもの（リンクのコピー、その他のSNS）
- スマホでのWeb Share API（`navigator.share`）による端末標準の共有シート
- シェア数の表示（各サービスのAPI依存のため持たない）

| 要素 | 仕様 |
|---|---|
| パンくず | `HOME`（リンク→`/`）＞ `プロフィール`。詳細ページ・トップページの絞り込み時と同じ部品を再利用する |
| ページタイトル | h1「プロフィール」＋下に罫線 |
| メイン画像 | 任意。角丸、横長（16:9または3:2）。未設定なら非表示 |
| 本文 | microCMSのリッチエディタHTML。「何をしている人か」「経歴」「スキル」などの見出し（h2）で区切る。h2は左に青いアクセントラインなど、MARGINのトーンで装飾する。記事詳細の本文スタイルを共用する |
| サイドバー | 他ページと共通（検索・著者カード・カテゴリー・アーカイブ・メッセージ枠）。プロフィールページ上の著者カードは本文と重複するが、現状は他ページと同じく表示している（非表示にする案もある） |
| シェアボタン | 参考画像にはあるが、**MVP対象外**（シェアの対象は記事に限る。記事詳細のシェアボタンは[6.1](#61-シェアボタンsharebuttons)参照） |
| SNSアイコン | 著者カード内に表示する想定（本文内には置かない）。未実装 |

- 著者がどんな人で、どんな技術を扱っているかが読者に伝わるよう、**経歴・使用技術・得意領域・連絡方法**を本文に載せる（掲載内容は運営者が決める）
- SEO: `generateMetadata`で`title`=「プロフィール」、`description`=著者の`bio`

## 8.5 プライバシーポリシー（`/privacy-policy`）・免責事項（`/disclaimer`）

フッターのリンク先となる規約系ページ。構成は[このブログについて](#7-このブログについてabout)と同じにする。

- パンくず（`HOME` ＞ `プライバシーポリシー` ／ `HOME` ＞ `免責事項`）、h1（ページ名。`page.tsx`に固定で記述）、本文
- サイドバーは`/about`と同じく表示する（`SidebarLayout`）
- ヘッダーのナビには載せない（どの項目もアクティブ表示にしない）
- 本文は`/about`と同じくmicroCMSのオブジェクト形式（`privacy-policy`・`disclaimer`）で管理する（`external/microcms/privacy-policy.ts`・`disclaimer.ts`）。静的に書く案もあったが、運営者が管理画面から編集できるほうを採用した
- 掲載内容の例: プライバシーポリシーはアクセス解析ツールの利用有無・問い合わせで得た情報の扱い、免責事項は掲載情報の正確性・リンク先の責任・著作権の扱い（文面は運営者が決める）
- SEO: 静的な`metadata`で`title`をページ名に、`description`を固定文にする

## 8.6 404ページ（not-found）

存在しないURL、または存在しない記事IDにアクセスしたときに表示するページ。

```
┌ ヘッダー ─────────────────────────────────────────┐
│                                                    │
│        ページが見つかりませんでした（h1）          │
│  お探しのページは削除されたか、URLが間違っている   │
│  可能性があります。                                │
│              [ HOMEへ戻る ]                        │
│                                                    │
└ フッター ─────────────────────────────────────────┘
```

| 項目 | 仕様 |
|---|---|
| ファイル | `app/not-found.tsx`（ルートに1つだけ置く）。どのルートにも一致しないURLと、記事詳細で`notFound()`を呼んだ場合の両方でこのページが使われる |
| レイアウト | ルートの`layout.tsx`の中で描画されるため、ヘッダー・フッターは自動で付く。パンくずとサイドバーは出さない（サイドバーはmicroCMSへの取得が必要で、エラー時の表示がCMSの状態に左右されないようにするため） |
| 見出し | `PageTitle`で`ページが見つかりませんでした` |
| 本文 | `お探しのページは削除されたか、URLが間違っている可能性があります。` |
| 導線 | `HOMEへ戻る`ボタン（`/`への内部リンク。daisyUIの`btn`） |
| メタデータ | 設定しない（タブはルートの既定値`KAIZEN 技術ブログ`になる）。Next.js 16のドキュメントで`metadata`のexportが案内されているのは`global-not-found.js`だけで、通常の`not-found.tsx`では対象外のため。Next.jsが404ページに`noindex`を付けるので、検索エンジンには登録されない |

- 記事詳細では、`generateMetadata`とページ本体の両方で記事が無ければ`notFound()`を呼ぶ。本文の送信（ストリーミング）が始まる前に呼ばれればHTTPステータスは404になり、始まった後でもNext.jsが`noindex`を付ける
- 記事が「存在しない」場合だけ404にし、microCMSの障害（ネットワークエラー、認証エラー等）は404にしない。障害を404として扱うと、一時的な障害で検索エンジンから記事が消えるため。404の判定は`external/microcms/blogs.ts`の`getBlogDetail`で行う（[07_api_design.md](./07_api_design.md)の3章参照）

## 8.7 エラー画面（error）

microCMSへの接続失敗など、ページの描画中に予期しないエラーが起きたときに表示するページ。存在しない記事は404（[8.6](#86-404ページnot-found)）で扱い、こちらには来ない。

| 項目 | 仕様 |
|---|---|
| ファイル | `app/error.tsx`（ルートに1つ）。Next.jsの決まりでClient Component（`"use client"`）にする |
| 受け取る値 | `error`（`digest`付きのError）と`retry`。Next.js 16では再試行の関数は`retry`（データを取り直して再描画する）。`reset`もあるが、データを取り直さないため使わない |
| 見出し | `PageTitle`で`エラーが発生しました` |
| 本文 | `ページの読み込み中に問題が発生しました。時間をおいて、もう一度お試しください。`（`global-error.tsx`は`時間をおいて、もう一度お試しください。`のみ） |
| 導線 | `もう一度読み込む`ボタン（`retry()`を呼ぶ）と`HOMEへ戻る`リンク |
| エラー内容 | 画面には出さない（本番ではServer Componentのエラー内容はNext.jsが伏せる）。`useEffect`で`console.error(error)`を出し、ブラウザの開発者ツールで追えるようにする |
| レイアウト | 404ページと同じく、パンくず・サイドバーなしの中央寄せ。ヘッダー・フッターはルートの`layout.tsx`のものがそのまま付く |

- `app/error.tsx`はルートの`layout.tsx`自体のエラー（`metadataBase`の`SITE_URL`未設定など）は受け止められない。そのため、最小限の`app/global-error.tsx`も置く。こちらは`layout.tsx`の代わりに描画されるので、自分で`<html lang="ja">`と`<body>`を持ち、`globals.css`を読み込む。メタデータのexportは使えないため、Reactの`<title>`要素でタイトルを付ける

## 10. アクセシビリティ・SEO

- ナビは`<nav aria-label>`（`メインナビゲーション`・`モバイルナビゲーション`・`パンくずリスト`・`ページネーション`・`フッター`・`記事をシェア`）、現在ページに`aria-current="page"`
- アイコンだけのボタン（モバイルメニューの検索・メニュー・閉じる、ScrollTop）には`aria-label`を付け、SVGは`aria-hidden`にする
- `<main>`はページに1つだけにする。ルートの`app/layout.tsx`が全ページを`<main>`で包むため、`SidebarLayout`などのページ内の部品では`<main>`を使わず`<div>`にする（404ページのようにSidebarLayoutを使わないページでも、main が必ず1つになる）
- フッターは`<footer>`要素で囲み、リンク行は`<nav aria-label="フッター">`＋`<ul>`／`<li>`で組む（ヘッダーのナビと区別できるラベルを付ける）
- 記事カードはカード全体を1つのリンクにし、リンクが重複して読み上げられないようにする
- アイキャッチ・メイン画像は`alt=""`（情報はタイトル側にあるため）
- 色だけに頼らない（ページネーションの現在ページは色＋`aria-current="page"`、無効な前へ／次へは`aria-disabled`）
- ページごとに`title` / `description`を設定する（[10.1](#101-ページごとのメタデータ)参照）
- シェアボタンはアイコンのみで文字がないため、各リンクに`aria-label`（ツールチップと同じ文言。新規タブで開く旨も伝えるなら`（新しいタブで開く）`を付ける）を付ける。アイコンのSVGは`aria-hidden`にする。ボタン群は`<nav aria-label="記事をシェア">`＋`<ul>`／`<li>`で組む
- 見出しは各ページでh1を1つにする（トップは絞り込み時のみ`「◯◯」の記事一覧`／`◯年◯月の記事一覧`。絞り込みなし時はh1なし。詳細は記事タイトル。[5.1](#51-パンくずと見出しの切り替え)参照）

### 10.1 ページごとのメタデータ

ルートの`layout.tsx`でサイト名を含む既定値とタイトルのテンプレートを持ち、各ページは自分のページ名だけを返す。ブラウザのタブには`ページ名 | KAIZEN 技術ブログ`と表示される。

| ページ | title | description | 設定方法・備考 |
|---|---|---|---|
| ルート（既定値） | `KAIZEN 技術ブログ`（`title.default`）。子ページは`title.template: "%s \| KAIZEN 技術ブログ"` | キャッチコピー（`つくって、試して、わかったこと。Web開発の学びをここに。`） | `layout.tsx`の`metadata`。`metadataBase`・`openGraph`（`siteName`・`locale: "ja_JP"`・`type: "website"`）もここで持つ |
| トップ（絞り込みなし） | 既定値のまま | 既定値のまま | `canonical`は`/` |
| トップ（カテゴリ絞り込み） | `「React」の記事一覧` | `「React」に関する記事の一覧です。` | `generateMetadata`で`searchParams`から組み立てる。見出し（h1）と同じ文言にする。`canonical`は`/?category=React`（`page`・`pageSize`を除く） |
| トップ（月絞り込み） | `2026年9月の記事一覧` | `2026年9月に公開した記事の一覧です。` | 同上（`canonical`は`/?month=2026-09`） |
| トップ（キーワード検索） | `「◯◯」の検索結果` | 既定値のまま | `robots: { index: false, follow: true }`。検索結果のページは任意の文字列で無数に作れるため、検索エンジンに登録しない（リンク先は辿ってよい）。カテゴリ・月と同時に指定されていても検索結果として扱う |
| このブログについて | `このブログについて` | 固定文（ブログの紹介） | `page.tsx`の`metadata`（静的） |
| プロフィール | `プロフィール` | 著者の`bio` | `generateMetadata`で`getProfile`を呼ぶ |
| プライバシーポリシー | `プライバシーポリシー` | 固定文 | `metadata`（静的） |
| 免責事項 | `免責事項` | 固定文 | `metadata`（静的） |
| 記事詳細 | 記事タイトル | `excerpt`（未入力なら既定値） | `features/blog-detail/lib/article-metadata.ts`。`canonical`は`/blogs/{id}`。OGPは`type: "article"`・`publishedTime`・アイキャッチ画像付き（[6.1](#61-シェアボタンsharebuttons)参照）。`openGraph`はルートの値と浅くマージされ丸ごと置き換わるため、`siteName`・`locale`もここで指定し直す |
| 404 | 既定値のまま | 既定値のまま | `not-found.tsx`はメタデータのexport対象外のため設定しない（[8.6](#86-404ページnot-found)参照） |

- サイト名（`KAIZEN 技術ブログ`）とキャッチコピーは`shared/lib/constants.ts`に定数（`SITE_NAME`・`SITE_DESCRIPTION`＝`CATCH_COPY.subtitle`）として持ち、`layout.tsx`・`manifest.ts`・ヘッダー・`global-error.tsx`で共用する
- トップページのtitle・descriptionの組み立ては、絞り込み条件による分岐があるため`features/blog-list/lib/`の関数に置き、`page.tsx`には持たせない。見出し（h1）の文言を作る処理と共通化する
- ページネーションの2ページ目以降は、titleを変えずに既定値（または絞り込みのtitle）のままとする

### 10.2 サイトマップとrobots.txt

検索エンジンに、サイト内のページと記事のURLを伝える。Next.jsのファイル規約（`app/sitemap.ts`・`app/robots.ts`）で生成し、`/sitemap.xml`・`/robots.txt`として配信される。

**サイトマップ（`app/sitemap.ts`）**

| 対象 | URL | `lastModified` |
|---|---|---|
| トップ | `/` | 最新記事の更新日時 |
| 固定ページ | `/about`・`/profile`・`/privacy-policy`・`/disclaimer` | 持たない（microCMSから取得しないため。取得のための通信を増やさない） |
| 記事詳細 | 全記事の`/blogs/[id]` | 各記事の`revisedAt`（最後に公開し直した日時）。無ければ`publishedAt` |

- URLは`shared/lib/site-url.ts`の`buildAbsoluteUrl`で絶対URLにする（サイトマップは絶対URLが必要）。現状の`app/sitemap.ts`は`process.env.SITE_URL`を直接連結しているため、`buildAbsoluteUrl`に揃えるのが残課題（[05_development_guide.md](../../frontend/docs/05_development_guide.md)の「残課題」参照）
- 記事一覧は`getBlogList()`をそのまま使う。キャッシュ（[07_api_design.md](./07_api_design.md)の5章）が効くので、サイトマップのために余分な通信は起きない
- カテゴリ・月の絞り込みページ（`/?category=…`）と検索結果は載せない。前者は記事詳細から辿れ、後者は`noindex`のため
- 記事の配列からサイトマップの配列を作る処理は`features/blog-detail/lib/sitemap-entries.ts`に切り出し、`app/sitemap.ts`は取得と呼び出しだけにする。`revisedAt`が無いときの分岐があるのでテストを書く
- `sitemap-entries.ts`は絶対URLを作る関数を引数で受け取る（`buildAbsoluteUrl`を直接importしない）。`site-url.ts`は`server-only`のため、直接importするとテストで読み込めなくなるのを避ける

**robots.txt（`app/robots.ts`）**

| 項目 | 値 |
|---|---|
| `rules` | すべてのクローラー（`userAgent: "*"`）に全体を許可（`allow: "/"`）。`/api/`は`disallow` |
| `sitemap` | `buildAbsoluteUrl("/sitemap.xml")` |

## 12. PWA

ホーム画面への追加（インストール）に対応する。Next.js公式のPWAガイド（`node_modules/next/dist/docs/01-app/02-guides/progressive-web-apps.md`）に沿い、ライブラリは追加せずにNext.jsの標準機能だけで実現する。

### 12.1 対応範囲

| 機能 | 対応 | 理由 |
|---|---|---|
| ホーム画面への追加（インストール） | **対応** | マニフェストを置くだけで実現でき、公式ガイドでも「オフライン対応なしでインストールできる」とされている |

| プッシュ通知 | 対象外 | 購読情報を保存するDBとVAPIDキーの管理が必要で、DBを持たない本プロジェクトの方針（[01_requirements.md](./01_requirements.md)）に合わない |

| `icons` | 192×192と512×512のPNG（白背景）。512×512は`purpose: "maskable"`用にもう1枚（淡い青`#EEF2FF`の背景で、絵柄を中央60%に収めたもの）を用意する |

- アイコンのPNGは既存の`app/icon.svg`（ファビコン）から書き出し、`public/icons/`に置いた（`icon-192.png`・`icon-512.png`・`icon-maskable-512.png`。macOS標準の`qlmanage`で変換）。ファビコンを変えたら作り直す
- 現状の`app/manifest.ts`は`/icons/icon-192x192.png`・`/icons/icon-512x512.png`を参照しており、実際のファイル名（`icon-192.png`・`icon-512.png`）と一致していない。また`maskable`のアイコンが登録されていない（[05_development_guide.md](../../frontend/docs/05_development_guide.md)の「残課題」参照）
- `maskable`は、Androidでアイコンが円や角丸に切り抜かれても絵柄が欠けないようにするための指定。中央の約80%に絵柄を収める
- iOSのホーム画面用アイコンは既存の`app/apple-icon.png`（180×180）がそのまま使われる
- アドレスバー等の色は、`layout.tsx`で`viewport`の`themeColor`に`theme_color`と同じ値を設定する（Next.js 16では`themeColor`は`metadata`ではなく`viewport`に書く）

### 12.3 確認方法

- ローカルでは`next dev --experimental-https`でHTTPSにすると、インストールの動作を確認できる（PWAはHTTPSが必須。`localhost`は例外的にHTTPでも可）
- ChromeのDevToolsの「Application」タブ → 「Manifest」で、マニフェストの読み込みとアイコンの表示、インストール可否のエラーを確認する
- 本番（Vercel）ではHTTPSのため、スマホで「ホーム画面に追加」できることを確認する
