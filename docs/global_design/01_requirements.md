# 要件定義書

## 背景

- 自分で運用し続ける技術ブログを構築する。日々の技術学習のアウトプットを残す場であると同時に、技術選定・設計・実装を実際のサービス上で検証する場（技術検証・設計検証）として位置づける。
- 作って終わりではなく、記事を書き続け、機能を足し、保守していくことを前提にする。その過程で設計判断を積み重ね、設計力を高めることも目的に含む。
- デザインは「MARGIN | TECH JOURNAL」というモックとして作成済みで、本ドキュメントはこのモックを実装するための設計をまとめたもの。

## 目的

- モックで示されたデザイン・機能をNext.js（App Router）+ microCMSで実装する。
- [immortal-architecture-mvp](https://github.com/YukiOnishi1129/immortal-architecture-mvp)、[Next.js App Router アーキテクチャの設計思想](https://zenn.dev/yukionishi/articles/cd79e39ea6c172) を参考に、意図の伝わる層構造を持つコードベースにする。参考元の設計思想を小規模なサービスに当てはめたときに、どこを採用しどこを簡略化するかを検証し、その判断をドキュメントに残す。

## 機能要件

### 共通レイアウト

- ヘッダー: ロゴ（MARGIN / 技術ブログ）、ナビゲーション（記事一覧・このブログについて・プロフィール。いずれも内部リンク）、キャッチコピー（`つくって、試して、わかったこと。Web開発の学びをここに。`）。キャッチコピーはページによらず全ページ共通でヘッダーの一部として表示する（PCのみ。スマホ・タブレットではヘッダーを1段に収めるため非表示）。スマホ・タブレットではナビの代わりに検索ボタンとメニューボタンを置き、それぞれダイアログで開く
- フッター: リンク行（HOME・プライバシーポリシー・免責事項）とコピーライト（`© 2026 KAIZEN.`）のみのシンプルな構成。紺の全幅帯に白文字で中央寄せ。ロゴとページ先頭へ戻るリンクは持たない（ロゴはヘッダー、ページ先頭へ戻る操作は右下固定のボタンが担う。詳細は[04_ui_design.md](./04_ui_design.md)参照）

### トップページ（`/`）… 記事一覧を兼ねる

> 旧案にあった「記事一覧ページ（`/blogs`）」は廃止し、トップページに統合する。トップページの「最新記事セクション」が全記事のページネーション一覧を兼ねるため、別ページへの遷移なしに全件へアクセスできる（詳細は[04_ui_design.md](./04_ui_design.md)参照）。

- ヘッダー直下のパンくず: カテゴリ・月の絞り込み時のみ`HOME > カテゴリ名`または`HOME > YYYY年M月`を表示する（絞り込みなし時は非表示）。旧案にあった大見出し「技術と、日々の余白。」は廃止した（詳細は[04_ui_design.md](./04_ui_design.md)参照）
- 最新記事セクション
  - 見出し: 絞り込みなし時は見出しテキストを表示しない。カテゴリ・月で絞り込んだときのみ`「◯◯」の記事一覧` / `◯年◯月の記事一覧`を表示する
  - カテゴリ絞り込み: 一覧上部のタブは持たず、サイドバーの「カテゴリー」一覧から行う（月の絞り込みと同じ構造）
  - 記事カード一覧（下記「記事カード」参照）。フィルタ・検索後の該当記事を対象に、ページ単位で表示する
  - 件数表示（「◯件中 ◯〜◯件を表示」）
  - 表示件数セレクト（10 / 20 / 30件など。既定10件）
  - ページネーション（前へ・ページ番号・次へ）
- サイドバー
  - 記事検索ボックス
  - 著者情報カード（アバター、名前、肩書き、自己紹介、内部プロフィールページ`/profile`へのリンク）
  - 記事検索はサイドバーの検索ボックスのほか、スマホ・タブレットではヘッダーの検索ボタンからも行える
  - カテゴリ一覧（「カテゴリー」、カテゴリごとの記事数）
  - アーカイブ（年月ごとの記事数）
  - 一言メッセージ枠（引用的なコピー）

### 記事カード

- サムネイル（アイキャッチ画像があればそれを表示。未設定なら、先頭カテゴリ名の大きな装飾文字＋小さなキャプション文字`MARGIN / TECH NOTE`で描画し、先頭カテゴリごとに配色を変える）
- 投稿日、「新着」バッジ（新着記事のみ）
- タイトル（要約文は表示しない。タイトルで内容が伝わるため。要約はmicroCMSに残し、検索結果・SNSカード用の説明文にのみ使う）
- カテゴリタグ（複数可）

### 記事詳細ページ（`/blogs/[id]`）

- パンくず（HOME > 記事タイトル）、タイトル、投稿日、本文（microCMSのリッチエディタ由来のHTML）
- シェアボタン（X・Facebook・はてなブックマーク）。Qiitaの記事詳細と同様に、PCでは本文の左側に縦並びで追従表示し、アイコンにカーソルを当てると「◯◯でシェアする」のツールチップを出す。クリックで各サービスの共有画面を新規タブで開く（詳細は[04_ui_design.md](./04_ui_design.md)の6.1参照）

### このブログについてページ（`/about`、新規）

- ブログのコンセプト説明。パンくず（HOME > このブログについて）＋見出し（`「KAIZEN」ブログについて`）＋メイン画像（任意）＋本文
- 本文はmicroCMSの`about`（オブジェクト形式）で管理する（以前の案では定数管理としていたが、`profile`と同様に運営者が管理画面から編集できるようCMS管理に変更した）

### プロフィールページ（`/profile`、新規）

- 著者の自己紹介を掲載する内部ページ（外部サイトへは遷移しない）
- パンくず（HOME > プロフィール）、ページタイトル、メインビジュアル画像（任意）、本文（自己紹介・経歴・スキルなど。見出しを含む長めの文章）
- サイドバー（検索・著者カード・カテゴリ・アーカイブ）は他ページと共通
- 著者カードのSNSアイコン（GitHub / X など）は外部リンクとして持つ（microCMSの`snsLinks`フィールドと型は用意済みだが、画面への表示は未実装）
- 内容はmicroCMSの`profile`（オブジェクト形式）で管理する

### プライバシーポリシー（`/privacy-policy`、新規）・免責事項（`/disclaimer`、新規）

- フッターのリンク先となる規約系ページ。パンくず（HOME > ページ名）＋見出し＋本文で、構成は`/about`と同じ
- 本文はmicroCMSのオブジェクト形式（`privacy-policy`・`disclaimer`）で管理する。`/about`と同じく、運営者が管理画面から編集できるようにするため

## 非機能要件

- コンテンツソースはmicroCMSのみとする。Qiitaからの記事取得は当初予定していたが、**スコープ外とする**（旧実装の`app/api/qiita/route.ts`等は撤去済み。詳細は[frontend/05_development_guide.md](../../frontend/docs/05_development_guide.md)参照）。
- 認証機能は持たない（読み取り専用の公開ブログ）。
- 独自DBは持たない（microCMSをデータソースとする）。
- レスポンシブ対応（PC・タブレット・スマートフォン）。
- SEOを意識したメタデータ（Next.jsの`metadata` / `generateMetadata`）を各ページに設定する。ページごとのtitle・descriptionは[04_ui_design.md](./04_ui_design.md)の10.1参照。
- 存在しないURL・記事IDには404ページを返す（`notFound()`と`app/not-found.tsx`）。
- microCMSのリッチエディタHTMLは、描画前にサーバー側でサニタイズする（[07_api_design.md](./07_api_design.md)参照）。
- サイトマップ（`/sitemap.xml`）と`robots.txt`を配信し、検索エンジンに記事のURLを伝える（[04_ui_design.md](./04_ui_design.md)の10.2参照）。
- microCMSの記事は1時間キャッシュし、公開・更新時はWebhookで即時に反映する（[07_api_design.md](./07_api_design.md)の5章参照）。
- PWAとしてホーム画面に追加（インストール）できるようにする。オフライン対応・プッシュ通知はスコープ外（[04_ui_design.md](./04_ui_design.md)の12章参照）。
- デプロイはVercel（現行構成から変更なし）。本番URLは`https://www.kaizen-tech-blog.com`。ドメインはCloudflare Registrarで取得し、DNSもCloudflareで管理する（Vercel向けのレコードはプロキシなしの「DNSのみ」）。`kaizen-tech-blog.com`（wwwなし）へのアクセスはVercel側で`www`付きへリダイレクトする。
